Custom IDE Builder

Executive overview

Custom IDE Builder makes a copy of the Code on the Go installed on this device, with the plugins and templates you choose bundled inside it, and signs the copy with your own key. Use it to hand out a version of Code on the Go that arrives with the add-ons a class, a team or a community needs already in place.

Read this before you install a copy. The copy is signed with your key, not ours, so Android treats it as a different app. It installs only after Code on the Go has been uninstalled, and uninstalling erases the projects stored in the app's data. Copy your projects out first.

Core functionality

  • Bundle swap. The plugins (.cgp) and templates (.cgt) you choose replace the add-ons bundled in the copy. Choosing nothing makes a copy that carries no add-ons.
  • Add-ons from two places. Pick files from this device, or choose from the add-ons website, which lists the ones that work with this version of Code on the Go.
  • Signing. The copy is signed with a key from your own keystore, and the signature is checked before the file is saved.
  • Your own name and icon (optional). The copy can carry a name and a launcher icon of your choosing instead of Code on the Go's, so it is not mistaken for the original.
  • Checks before it is built. The name, the picture and each plugin's requirements are checked, and you confirm the name and icon are yours.
  • Output folder. The finished APK is saved to a folder you choose, as <app name>-<version>-custom.apk.
  • Release builds only. It is made for the release build of Code on the Go, which reads its bundled add-ons from assets/plugins/ and assets/templates/ in its APK.
  • Installing the copy. It installs only after Code on the Go is uninstalled, because it is signed with a different key.

Technical architecture

  • The installed app's APK is copied entry by entry without being recompressed. The old bundle (assets/plugins/, assets/templates/ and the index assets/bundled-addons.tsv) and the old signature are dropped, then your add-ons and a new index are added, in the layout Code on the Go itself reads.
  • Each add-on gets a clean file name inside the APK. A plugin is named after its plugin ID, a template after its file name, and two that would clash are refused before the build starts.
  • Renaming replaces Code on the Go in the app's text resources and manifest, for every language the app carries. The picture is cropped to a square and drawn as the launcher icon, the splash-screen picture, the logo on the app's own screens (welcome, main screen, About and the editor sidebar) and a white-outline status-bar icon, at every screen density.
  • The name is refused if it is blank, over 50 characters, or close to Code on the Go or its short form (look-alike letters and spaces do not fool the comparison). The picture is compared with Code on the Go's own icon as the launcher, older launchers and the app's own screens draw it, with and without its margins, and refused if it looks like any of them.
  • For each plugin the builder reads its plugin ID and the lowest Android version it needs from the plugin's compiled manifest, reading at most 1 MiB of it, so a plugin made for a newer Android than this device's is still recognised. It compares that version with the Android version this copy of Code on the Go supports.
  • The APK is signed with the Android signing library (apksig) and then verified with it, and its alignment is checked.
  • Files you pick are copied into this plugin's own private folder under a fixed name, whatever the file is called, before they are checked. Downloads from the website come only from addons.appdevforall.org over HTTPS and are checked against the size and SHA-256 the website publishes.
  • Passwords are held only in the screen's fields and in the one running build. The build's copies are zeroed, and the fields are emptied, when a build ends, however it ends; the fields are also emptied when you leave the screen. The plugin asks for permission to read and write files and to use the network (for the website list only).

Usage

What you need

  • A keystore file in PKCS12 (.p12) or BKS format, such as one made by Keystore Generator. A Java KeyStore (.jks) file made by keytool must be converted first, on a computer: keytool -importkeystore -srckeystore old.jks -srcstoretype JKS -destkeystore new.p12 -deststoretype PKCS12.
  • The add-ons: .cgp plugin files and .cgt template files from this device, or downloaded from the add-ons website.
  • A folder to save the finished APK in, and free space for about twice the size of Code on the Go.

How to use it

  1. Open Custom IDE Builder from the main menu.
  2. Add-ons. Tap Add from this device to pick several files at once. Tap Add from the website to choose from the add-ons that work with this version of Code on the Go. Nothing is downloaded until you confirm; the downloads come from addons.appdevforall.org and each one is checked against the size and SHA-256 the website publishes. Tap Remove beside an add-on to take it off the list.
  3. Name and icon (optional). Type a name for the copy and tap Choose icon to pick a picture; leave them empty to keep the ones Code on the Go has. The name replaces Code on the Go on the launcher and wherever the app shows its own name. When you choose either one, tick This name and icon are my own, and not Code on the Go's; the build will not start until you do. The builder refuses a blank name, a name over 50 characters, a name that is close to Code on the Go, and a picture that looks like Code on the Go's own icon.
  4. Signing key. Choose the keystore file, type the store password and tap Read keys, then pick the key. Leave the key password blank if it is the same as the store password.
  5. Output folder. Choose it once; it is remembered.
  6. Tap Build APK. Tap Cancel to stop it. A cancelled or failed build saves nothing: if it had already begun writing the APK to your folder, that unfinished file is deleted. The file is saved as <app name>-<version>-custom.apk, using your name if you gave one.

Long-press any button or field on the screen for a short explanation.

Key benefits

  • Hand out one APK that arrives with the plugins and templates a group needs, with nothing to install afterwards.
  • It is signed with your key, so you decide who the publisher is, and it can carry your own name and icon.
  • It works offline once you have the files, and does not need a computer.
  • Every download and every selection is checked before it goes into the copy.
  • Your passwords are never saved.

Good to know

  • Use the same key every time. A device that has a build signed with one key cannot update to a build signed with another without being uninstalled first.
  • Passwords are never saved. They are used for the build in front of you and cleared when a build ends and when you leave the screen.
  • Each plugin must have its own plugin ID and each template its own file name; the builder says which add-ons clash. core.cgt is never bundled, because Code on the Go installs it itself.
  • A plugin can need a newer Android than this copy of Code on the Go does. The screen then warns, naming the Android version the plugin needs (and this device's, when it is older too), and you decide whether to keep it or remove it. If the plugin's requirement cannot be read (or its manifest is too large to read), it says so with a softer warning.
  • Some text keeps the original name on purpose: the credit line added to Git commits, the link to Code on the Go's download page and the invitation to contribute to the project. Text that carries formatting and names Code on the Go on an older version of the app is also left as it is; the screen reports how many.
  • Check the result on a device. Install the copy and look at the launcher, the splash screen, the logo on the welcome and main screens and a notification. A picture with a clear shape on a plain or transparent background gives the best status-bar icon.
  • Nothing chosen makes a copy that carries no add-ons.
  • The copy is built from the APK of this installation. It does not work if Code on the Go was installed as split APKs; the screen says so.
  • The app is copied without being recompressed, so building takes about as long as copying the file, plus the time to sign it.
