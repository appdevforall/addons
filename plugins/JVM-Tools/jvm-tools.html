1. Executive Overview

JVM Tools runs Java and Kotlin programs the way a desktop IDE does: choose the class whose main should start, give it program arguments, and tap Run. The project is compiled on the device with the JDK and Kotlin compiler that Code on the Go already ships, and the output streams into Build Output. Nothing is downloaded.

It applies to JVM projects only: a folder of .java and .kt files with no Gradle build. Android projects keep their Gradle toolbar untouched.

3. Technical Architecture

Domain gating

JvmDomain treats the open project as JVM when its root has no Gradle build file and a .java or .kt file sits within four folders of it. Every contribution below is gated on that check, so the plugin is invisible in Android projects.

Finding main classes

MainClassFinder reads the sources with comments removed and reports Java classes with a static void main(String[]), Kotlin files with a top-level fun main (as the FileNameKt facade, or the @file:JvmName), and Kotlin objects or companion objects with a @JvmStatic main. Names are qualified with the file's package.

Compiling and running

Run is a PluginBuildAction whose shell command:

  1. lists the project's sources, skipping build/ and dot folders;
  2. compiles all sources with K2JVMCompiler from kotlin-compiler-embeddable in the IDE's local Maven repository, when any .kt file exists (Java files are passed too, so Kotlin can see Java classes);
  3. compiles the .java files with the JDK's javac against the Kotlin output;
  4. replaces itself with java -cp classes[:kotlin-stdlib] MainClass args..., so cancelling the action stops the program.

Classes are written to a per-project folder under $PREFIX/tmp/jvm-tools, never into the project. The toolchain paths come from IdeEnvironmentService.getTmpDirectory(), whose parent is $PREFIX.

Hiding the Gradle actions

toolbarActionsToHide() returns ToolbarActionIds.BUILD_HIDEABLE, and getHiddenToolbarActionIds() adds Quick Build, which is not in that set.

Permissions: filesystem.read, filesystem.write, system.commands, project.structure. Supports Code on the Go 26.37 through 26.99; 26.37 is the first release with PluginWindows, which shows the Run configuration dialog.

5. Usage

  1. Install the plugin from the Plugin Manager and restart Code on the Go.
  2. Create a project with Java/Kotlin Program on the New Project screen, or open a folder of .java and .kt files.
  3. Tap Run. The project compiles and the output appears in Build Output.
  4. To run another class or pass arguments, tap Run configuration, choose the main class, enter the arguments, and tap Save. Run uses that choice from then on.

Build the plugin itself with ../../gradlew assemblePlugin from plugins/JVM-Tools.

6. Key Benefits

  • Runs Java and Kotlin programs with no Gradle project, no network and no extra downloads.
  • Works like a desktop IDE: pick the main class and arguments once, then run with one tap.
  • Leaves Android projects untouched; the toolbar changes only in a JVM project.

7. Limits

  • No keyboard input: plugin commands have no stdin, so Scanner and readLine() see the end of input.
  • No third-party libraries: only the Java class library and the Kotlin standard library are on the classpath.
  • A main in a nested Java class is not listed.
