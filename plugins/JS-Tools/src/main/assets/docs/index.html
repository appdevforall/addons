JS Tools

Write, run, and test JavaScript and TypeScript on the device, with no network connection.

JS Tools adds three project templates, editing support for JavaScript and TypeScript files, and up to five toolbar commands. The commands appear only while a JavaScript or TypeScript project is open; in a Java, Kotlin, or Android project the toolbar is left alone. Because Gradle plays no part in these projects, the Gradle actions (Quick Run, Sync, Debug, Run Tasks, Launch App) are hidden while you work in one.

A project counts as JavaScript or TypeScript when its root holds a package.json, tsconfig.json, or jsconfig.json, or a .js, .ts, .jsx, or .tsx file in the root or in src/, and no Gradle build script.

Getting Node.js and TypeScript

Node.js 24 LTS, npm 11, TypeScript 6, and typescript-language-server ship inside the plugin, with a Node.js build for both 64-bit and 32-bit ARM devices. The first time the plugin activates it unpacks the build for this device into its own private directory - no download, no network, and nothing is installed into the shared terminal environment. It takes about 160 MB on the device and happens once; a message tells you when Node.js is ready.

Node.js is not installed with pkg. Code on the Go's package repository carries a curated subset that does not include Node.js, so the plugin carries Termux's build of Node.js together with the libraries it loads (ICU, OpenSSL, SQLite, c-ares, zlib, and libc++), and starts it with those libraries rather than the terminal's own.

Editing

Files ending in .js, .mjs, .cjs, .jsx, .ts, .mts, .cts, and .tsx get syntax highlighting from tree-sitter grammars, and completion, hover, signature help, go to definition, find references, and error squiggles from TypeScript's language service, which typescript-language-server serves to the editor.

The language server starts when you open the first file of a kind and stays running while the project is open. JavaScript, JSX, TypeScript, and TSX files each get their own server, so a project that mixes all four runs four. If you open a file before the first install has finished, close and reopen it once Node.js is ready.

The bundled templates include the Node.js type declarations in node_modules, so completion knows node:fs, node:http, and process from the first keystroke. In a project of your own, tap Install packages once you add @types/node to package.json.

Every command streams its output into the Build Output panel at the bottom of the editor, and the panel opens itself when a command starts. While a command is running its toolbar button turns into a Cancel button: tap it to stop the process.

Run app

Runs the project's entry point with Node.js. The entry point is, in order: the file named by a start script of the form node <file>; the main field of package.json; or a file named index or main with a .js or .ts extension in the project root or src/.

When the plugin finds the file itself it runs Node.js on it directly, so the process the IDE tracks is your program and Cancel really stops it. Any other start script runs through npm start; there, Cancel stops npm, and a server npm started can keep running. Write the start script as node <file> to avoid that.

Run current file

Appears while a .js, .mjs, .cjs, .ts, .mts, or .cts file is open, and runs exactly that file with Node.js - useful for a scratch script that is not the project's entry point. JSX and TSX files need a build step before Node.js can run them, so the command does not appear for them.

Run tests

Runs npm test when package.json defines a test script, and otherwise Node.js's built-in test runner, node --test, which finds files such as *.test.js and *.test.ts anywhere in the project. The built-in runner needs no packages, so tests work offline.

Type check

Appears when the project has a tsconfig.json or jsconfig.json, and runs tsc --noEmit with it: every type error in the project is listed, and nothing is written to disk. It is the same compiler as the language server, so the two report the same errors.

Install packages

Appears when the project has a package.json, and runs npm install in the project root.

This is the one command that needs a network connection. Packages are downloaded from the npm registry. A project that uses only Node.js's built-in modules never needs it - which is why the bundled templates have no dependencies to download, and run fine with no connection at all.

TypeScript without a build step

Node.js 24 runs .ts files directly: it removes the type annotations as it loads each file. That covers everything that is only types - annotations, interfaces, type aliases, generics, as casts - but not enum, namespace, or parameter properties, which need compiling. The TypeScript templates set erasableSyntaxOnly in tsconfig.json so the editor flags those as errors before you run.

Imports name the .ts file they load, as in import { greet } from './greet.ts'; allowImportingTsExtensions in tsconfig.json lets the type checker accept that.

The templates

JavaScript App is a small ES module program: a greet module, an entry point that calls it, tests for the built-in runner, and a jsconfig.json that type-checks the JavaScript.

TypeScript App is the same program in TypeScript with strict type checking.

Node.js Web Server is a TypeScript server on node:http with a text route, a JSON /api/hello route, a 404 for anything else, and graceful shutdown on SIGINT and SIGTERM. Run it and open http://localhost:3000 in a browser on the same device. Its tests start the server on a free port and call it with fetch.

All three ask for a package name when you create them, and use only Node.js's built-in modules.

Build environment

Commands run with these settings:

  • node, npm, npx, and tsc are on the PATH. node is a small launcher that points LD_LIBRARY_PATH at the libraries bundled with it.
  • npm keeps its cache and global packages in the plugin's private directory, runs package scripts with the terminal's sh, and skips the update, funding, and audit checks.
  • TMPDIR points at the IDE's temporary directory, and SSL_CERT_FILE at the terminal's certificate bundle, which npm needs to reach the registry over HTTPS.

Limits

  • Programs cannot read keyboard input: nothing typed reaches process.stdin of a command. Pass values as arguments or environment variables instead, or run the program from the terminal.
  • JSX and TSX files are highlighted and checked, but not run: running them needs a bundler.
