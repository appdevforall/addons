AI Core — Agent Guide

AI Core provides the Agent tab — a chat assistant that can read, search and edit your project through an approval-gated tool loop — and the inference router every other AI plugin uses.

It ships no model of its own. Install at least one backend plugin alongside it: AI Agent Local to run .gguf models on the device, or AI Agent Gemini to call Google's API. Without one, the Agent has nothing to talk to.

Where the settings live

The backend, the model and your Gemini API key are all configured on one screen, reached from Preferences → Configuration → Agent. The same screen opens from the Agent tab's sidebar (Settings, at the bottom), so you do not have to leave the chat to change something. Every setting saves as you change it.

Choosing a backend

The AI Backend list on the settings screen shows every backend plugin you have installed. Pick one and the panel below it changes to that backend's own settings — each backend supplies its own, so what you see depends on what you installed:

  • AI Agent Local — runs a .gguf model via llama.cpp. Its panel shows the engine status and a file picker for the model. Nothing leaves the device.
  • AI Agent Gemini — calls Google's API. Its panel takes an API key and lists the models that key can reach; see Getting a Gemini API key below. Prompts and any file contents the agent reads are sent to Google over HTTPS.

If the list is empty, no backend plugin is installed — add one from the Plugin Manager.

Will this model fit in memory?

When you pick a local .gguf file, it is measured against the RAM free on the device at that moment, before anything is loaded. If it looks too large you get a warning with the actual figures and two choices:

  • Cancel — nothing is saved and nothing is loaded. Whatever model you had selected before stays in use. Dismissing the warning with Back does the same thing.
  • Proceed anyway — the model is accepted despite the shortfall. Use this when you are about to close other apps, for example.

The warning quotes two numbers. Memory to load is the weights: these are memory-mapped, so they need not all fit at once — when they don't, the device pages them in and out, which is why an oversized model can stall for minutes instead of failing immediately. Memory to run is the KV cache and compute buffers, which are ordinary allocations and do have to fit. That is why a model can be reported as risky rather than impossible: the outcome genuinely depends on how much paging your device will tolerate.

To fit a large model, close other apps and select it again, or pick a smaller or more heavily quantized build. A Q4_K_M quantization of a 1–3B model is the most likely to run comfortably.

What the agent can do

  • Read and search files within the current project.
  • Create and update files (asks for approval before writing).
  • Edit part of a file — the agent proposes a find/replace change, and the approval dialog shows you the exact before/after before anything is written. You can Accept it, Decline it, or choose Correct to tell the agent what to change and let it try again. When the file is open in the editor, the change is applied to the buffer, so Ctrl+Z undoes it and your unsaved work is preserved.
  • Trigger a Gradle sync (asks for approval — a sync starts a real build) and read build output.
  • Add dependencies and generate code from templates, both after asking.
File tools are confined to the project root: paths that resolve outside it are rejected, so the model cannot read or overwrite arbitrary files on the device.

Tools from other plugins

Other plugins can give the agent tools of their own. AI Agent MCP is one: it connects to Model Context Protocol servers — issue trackers, documentation indexes, internal APIs — and their tools appear in the agent's list beside the built-in ones. Nothing is required here; with no such plugin installed the agent has exactly the tools listed above.

These tools are treated more cautiously than the agent's own, because only the plugin that supplied one knows what it does:

  • They ask every time. The approval dialog names the plugin the tool came from — From MCP servers, for example — and Always Allow does not apply to them, however you answer. A plugin cannot waive this for its own tools, and the title shows the name the agent registered rather than the one the tool came with, so a remote tool cannot pass itself off as a built-in one.
  • They are not confined to the project root. A contributed tool runs inside its own plugin, under the permissions that plugin declared, so one from a plugin with network access can send what it is given off the device. That is exactly why the dialog names the source and shows the arguments.
  • Only a limited number reach the model each message. A single remote server can advertise ninety tools, which would fill the whole context window on its own, so the agent describes the first twelve to the model. Enable the few you actually want in the providing plugin's settings.

Attaching context files

  • Tap the attach button beside the prompt to pick files whose contents are sent with your next message.
  • The picker is rooted at the project you have open and cannot browse above it. With no project open it declines to open at all.
  • Toggle All selects every file in the folder you are viewing; Add Selected attaches them as chips above the prompt.
  • On the Gemini backend, attached file contents leave the device.

Getting a Gemini API key

You do not need the Google Cloud console. Keys are created at aistudio.google.com/apikey, and Google AI Studio sets up the underlying Cloud project for you the first time you accept its terms.

  1. On the Agent settings screen with the Gemini backend selected, tap Get API Key. Your normal browser opens at AI Studio.
  2. Sign in with your Google account in the browser and tap Create API key. This plugin never sees your Google password.
  3. Copy the key Google shows you, return to the IDE and paste it into the Gemini API Key field (long-press the field, then Paste).
  4. Tap Save Key. The key is checked with Google immediately.

What Save reports:

  • Verified — your API key works — Google accepted the key and it has been stored.
  • Key accepted, Google is rate-limiting — the key is valid and stored; the quota is busy right now, not the credential.
  • Invalid API key — Google refused it, so nothing is saved. Check what you pasted and try again. Keys are long, single-line, and contain no spaces.
  • Couldn't reach Google / Couldn't check this key — the check itself failed (no network, or the AI Core plugin is disabled or out of date), so you are asked whether to keep the key anyway. Kept this way it is stored but not confirmed, and the status line says so.

If no browser is installed, the AI Studio link is copied to the clipboard so you can open it on another device and type the key in by hand.

AI Studio isn't available in every country. If you can't create a key, the Local backend needs no account at all — pick a .gguf chat model and everything runs on the device.

Free tier and your data

Gemini has a free tier that is enough to use this plugin. Be aware that on the free tier Google may use prompts and responses to improve its products; the paid tier does not. Because the agent sends your prompts, project context and the contents of files it reads, that applies to your code too. This has always been true of the Gemini backend — it is written down here so it isn't a surprise. The Local backend sends nothing anywhere.

Your Gemini API key

The key is encrypted with AES/GCM under a hardware-backed Android Keystore secret, and only the ciphertext is written to the plugin's private storage — a copied preferences file is useless without this device's Keystore. Clear it any time from Preferences → Configuration → Agent. If the Keystore entry is ever lost — clearing the app's data, for example — the stored key can no longer be read and will need to be entered again; tapping Edit tells you when that has happened.

Reading the conversation

  • Retry appears on a step that failed — including a tool call you declined — and runs your last prompt again with the same attached files, from the conversation as it stood before that attempt. The failed turn is dropped rather than left for the model to read, so a declined tool asks for approval again instead of the agent reporting that it was declined.
  • Open AI Settings appears instead when the agent has not been configured yet — no local model chosen, or no Gemini key saved. It opens the Agent settings screen directly.
  • System log rows are collapsed records of the agent's internal steps: tools run, files touched, backend errors. Tap the header to expand one. They are saved with the session but are not sent to the model.
  • Long-press a message to copy its text, or to edit and re-send one of your own.

Keeping several chats

Chats belong to the project they were started in. Opening a project shows that project's chats and no one else's, and you can keep as many as you want — one for a build failure, one for a refactor, one for the feature you are adding — instead of letting a single conversation collect all three.

The button at the top right of the Agent tab slides a sidebar in over the conversation. Its three parts are fixed in place except the middle one, which is the only part that scrolls:

  • New chat, at the top, starts a fresh conversation. The one you were in is kept, and you can go back to it whenever you like.
  • Recent, in the middle, lists this project's conversations, newest first, each named after its first message and dated from when it began, with a tick on the one you are in. It holds the newest to begin with and loads more as you scroll, so a project with a long history still opens at once. Tap a row to carry on with it: the agent reloads that conversation, so the next thing you send follows on from what was already said there — including after closing and reopening the IDE. If the agent is working when you switch, that run is stopped first, and whatever it had already done stays in the chat it belonged to.
  • Clear this chat, at the bottom, empties the conversation you are in and keeps you in it. This one does not keep a copy, so it asks you to confirm — and use New chat instead if you may want the old thread back.
  • Settings, beside it, opens the Agent settings screen.

New chat sits at the right of the panel's top row; the button at the left of that row closes the sidebar, as does tapping the dimmed conversation beside it or pressing Back.

The ⋮ button on a row in Recent renames or deletes that chat. A name you give it replaces the first-message title; clearing the name gives the first-message title back. Deleting cannot be undone — and deleting the last chat leaves you an empty one to carry on in, rather than nothing.

To clear out several at once, long-press a row. Every row gets a checkbox, tapping a row ticks it instead of opening it, and the bin at the top of the sidebar removes everything ticked in one step — with the same warning, since it cannot be undone either. The ✕ beside it returns to the ordinary list. Deleting every chat still leaves you one empty conversation to carry on in.

Only what you and the agent said is restored into a reopened conversation: attached file contents and the agent's internal tool steps are not, and a very long conversation is restored from its most recent turns so it still fits a small local model's context window.

Troubleshooting

  • "No model configured" — select a .gguf file (Local) or set an API key (Gemini) under Preferences → Configuration → Agent.
  • Gemini errors — check the API key, network connection, and quota. Re-tapping Save on the key re-runs the live check and tells you which of the three it is.
  • "Invalid API key" — the key was not stored. Make sure you copied the key itself from AI Studio and not the page's URL.
  • Agent tab missing — confirm AI Core is installed and enabled and the IDE was restarted.
  • The agent never uses a tool another plugin supplies — it is probably past the twelve the agent describes to the model. Turn off the ones you do not need in that plugin's own settings, then start a new message.
  • A tool from another plugin keeps failing — the failure belongs to that plugin, not to the Agent; the chat shows one sentence naming it, and the run carries on. Check that plugin's own settings.
