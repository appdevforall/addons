Go Tools

Build, run, and test Go programs on the device, straight from the editor toolbar.

Go Tools adds two project templates and four toolbar commands. The commands appear only while a Go project is open; in a Java, Kotlin, or Android project the toolbar is left alone. Because Gradle plays no part in a Go project, the Gradle actions (Quick Run, Sync, Debug, Run Tasks, Launch App) are hidden while you work in one.

A project counts as Go when its root holds a go.mod or any .go file, and no Gradle build script.

Getting the Go toolchain

The Go toolchain ships inside the plugin. The first time the plugin activates it unpacks Go into its own private directory - no download, no network, and nothing is installed into the shared Termux prefix. It takes about 250 MB on the device and happens once.

Go is deliberately not installed with pkg or apt. The bundled Termux does not ship the mirror list pkg needs, and Code on the Go's package repository carries a curated subset that does not include golang. The plugin is also pinned to Termux's build of Go rather than the one from go.dev, because the stock build cannot compile a project stored on the device's shared storage - see Shared storage.

Every command streams its output into the Build Output panel at the bottom of the editor, and the panel opens itself when a command starts. While a command is running its toolbar button turns into a Cancel button: tap it to stop the process.

Run app

Compiles the main package in the project root and executes the binary it produced.

The plugin builds and then executes, rather than using go run, for one reason: go run compiles your program and launches it as a child process, so the process the IDE is tracking is the compiler, not your program. Cancelling it stops the compiler and leaves your program running as an orphan - which matters most for a server, the thing you are most likely to want to stop. Building first makes the tracked process your program, so Cancel really stops it.

The binary is written into the IDE's temporary directory and overwritten on every run. If the build fails because a module is missing, go mod tidy runs for you and you are asked to tap Run again.

Run current file

Appears while a .go file that is not a test file is open, and builds exactly that file by its full path - useful for a scratch program that is not the module's entry point.

A single-file build sees only the file you point it at, so that file must declare package main with a main function and must not call into other files of the same package. For anything larger, use Run app.

Tidy modules

Runs go mod tidy in the project root. It reads every import in the module, adds what is missing to go.mod, drops what is no longer used, and refreshes go.sum.

This is the one command that needs a network connection. Modules are downloaded from the Go module proxy. A project that imports only the standard library never needs it - which is why both bundled templates are standard-library only, and run fine with no connection at all.

Run tests

Runs go test ./... from the project root, covering every package in the module. Go's test runner is part of the toolchain, so nothing extra is installed and tests work offline.

Build environment

Commands run with two settings that matter on a phone:

  • CGO_ENABLED=0 - the toolchain comes straight from go.dev and is not patched for Android's NDK layout, so its cgo path does not find a usable C compiler even though clang ships with the IDE. Pure-Go builds need none of that, and every standard-library package used by the bundled templates builds without cgo.
  • GOFLAGS=-buildvcs=false - Go stamps version-control metadata into binaries, and fails the build when it finds a .git directory but no git executable. That is the normal state on a device, so the stamping is turned off.
  • GOROOT, GOPATH, GOCACHE point into the plugin's data directory, and TMPDIR/GOTMPDIR point at the IDE's temporary directory. Without the last two, Go tries to create its work directory under /tmp, which no app can write to on Android, and every build fails before it starts.

The templates

Go Starter is a minimal module: a greet function, a main that calls it, and a table-driven test so Run tests has something to run on the first tap.

Go HTTP Server is a net/http server with an HTML landing page, a JSON /api/status route, request timeouts, and graceful shutdown on SIGTERM. Run it and open http://localhost:8080 in a browser on the same device.

Both ask for a module path when you create them (what goes on the module line of go.mod), and both import only the standard library.

Shared storage and the toolchain build

Your projects live on the device's shared storage. When Go loads a module it takes a file lock on go.mod, and shared storage on Android does not implement those locks. The toolchain published on go.dev fails immediately on every command with RLock ... function not implemented. Termux's build of Go handles it, which is the build this plugin carries.

This only shows up on a real project: a test run from the app's private directory succeeds with either build. If Go ever stops working after a toolchain change, this is the first thing to check.
