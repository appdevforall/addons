AI Agent MCP — Remote Tools for the Agent

AI Agent MCP connects Code on the Go's Agent to Model Context Protocol servers. A server you configure advertises tools — search a documentation index, open a ticket, query an internal API — and the Agent can call them the same way it calls its built-in tools.

Install AI Core as well, plus a model backend. This plugin adds tools; it does not add a model, and on its own it does nothing.

Adding a server

  • Open Preferences → Configuration → MCP servers and tap Add server.
  • Give it a name — it is also the prefix on that server's tool names, so two servers offering search stay distinguishable.
  • Enter the endpoint URL. It usually ends in /mcp.
  • Add an access token if the server needs one. It is encrypted with a key held in the Android Keystore, and sent only to that server, as an Authorization: Bearer header. Leaving the field empty keeps the stored token, so if you change a server's URL and leave it empty, the stored token is sent to the new URL. To send the new URL no token, use Clear stored credential first.
  • The URL must be https:// unless the server runs on this device. Plain http:// is accepted only for localhost, 127.0.0.1 or [::1], such as a server started in the Terminal, with or without a token; that traffic never leaves the phone. Anywhere else, your home network included, it would cross Wi-Fi in the clear, so Save refuses it. A server saved earlier with such a URL stays in the list, marked, and does not connect until you change it to https://.
  • Clear stored credential appears once something is stored. The token field never shows what it holds and leaving it empty keeps it, so this is the way back to a server that needs no credential at all — after pasting the wrong token, or when a server stops requiring one.
  • Tap Connect. It saves the server, checks it now, and lists the tools it offers below.

Choosing tools

Every tool starts switched off, with the one exception below. That is deliberate: each enabled tool costs prompt space on every message you send, and a large server can advertise ninety of them — enough to fill a phone-sized context window on its own. Switch on the handful you actually want.

The one exception is the SQLite debugger entry, which Code on the Go adds by itself for an app you build with the SQLite debugger, named "SQLite debugger (application ID)". Five of its read-only tools start switched on: list_databases, get_schema, query, get_events and read_sql_template (below). Its other tools start off. This version does not show the entry on the MCP servers screen, so it has no switches there yet.

The one switch it has is Let the Agent change app databases, at the top of the MCP servers screen, off at first. While it is on, every app's SQLite debugger entry also offers execute, which runs one SQL statement that changes data or the schema. The Agent asks for your approval before every change, and "Always Allow" is never offered for it. A change is saved at once and can't be undone. For an app that uses Room, the first change is refused until the Agent asks you again, because Room doesn't notice it and the app can show old data until it reads the database again.

The Agent reads this list from memory, so tap Connect again after the server changes; a chat that is already open picks the new list up.

SQL templates

read_sql_template is the sqlite3 shell's .read with a template: put a file ending in .sql.peb anywhere in your project, such as sqlite/report.sql.peb, and ask the Agent to read it. Code on the Go fills it in from your app's databases and gives the Agent the SQL. Nothing is run until the Agent runs it, one statement at a time.

Templates use the same Pebble syntax as Code on the Go's project templates: ${{ value }} prints, ${% for ... %} and ${% if ... %} control, ${# ... #} is a comment. A closing }}, %} or #} swallows the line break after it, so end such a line with a space to keep it. Quote a table or column name with | sql_ident and a value with | sql_literal. For a value you type, write a parameter such as :id instead, and the Agent binds it.

${# Row counts of every table, with Room's schema check #}
-- ${{ db.name }}: Room schema ${{ db.schema_matches ? "matches" : "differs or is not exported" }} 
${% for t in db.tables %}${% if t.type == "table" %}
SELECT ${{ t.name | sql_literal }} AS name, ${{ row_count(db, t.name) }} AS row_count;
${% endif %}${% endfor %}
SELECT * FROM ${{ "orders" | sql_ident }} WHERE customer_id = :id;

A template can use app, device, databases (every database's tables, columns, indexes and foreign keys, Room's identity hash and schema_matches), db (the database you named, or the only one), room_schemas (the schemas Room exported into your project), project and render_time. These functions read your app's data, only when the template calls them: row_count(db, table), distinct_values(db, table, column, limit), sample_rows(db, table, n), integrity(db), suggest_indexes(db, sql) and lint_foreign_keys(db). distinct_values and sample_rows return at most 1000 rows, and stop the template rather than give it part of the rows or a cut value.

Approval

Every remote tool asks for your approval before it runs, showing the arguments it would send. The exception is a read-only tool of the SQLite debugger, such as the five that start switched on: its dialog offers "Always Allow", which covers that tool for the rest of the chat. The grant is for that tool and that app only, it ends when you start or open another chat, and it ignores the arguments, so the Agent can then call the tool with any arguments. It rests on the plugin's own claim that the tool only reads, which Code on the Go cannot check. This needs AI Core 3.6.0 or later; an older AI Core asks on every call. The Agent's own file tools are confined to the open project; a remote tool is confined by nothing this device controls, so the dialog is the only gate — read it.

What is sent

  • The tool's arguments, as the model composed them, to that server only.
  • Nothing else: this plugin has network access, plus debugger.endpoints to read the SQLite debugger endpoints Code on the Go stores, and no other permission. It cannot read your project or your files. Anything from your project reaches a server only if the model puts it in an argument and you approve the call.
  • Server and tool names are reduced here to the alphabet a tool name may use, and the Agent flattens and caps every description a plugin contributes before it reaches the prompt — so a server cannot forge instructions with formatting.

Which servers work

Servers speaking MCP's Streamable HTTP transport, which is the one reachable from a phone. A server offering only the local stdio transport cannot be used, and the deprecated HTTP+SSE transport is not supported.

Known limits

Three rare session races are accepted for now:

  • A Save or Clear that changes only the credentials can leave one session open on a third-party server that needs the old token to end it. The session expires on the server.
  • A SQLite debugger entry's health follows the entry, not the port. After the app moves to a new port, a result from the old one can show for up to one 20-second probe cycle.
  • Two requests that both get a 404 for the same expired session can start an extra handshake and leave one session to expire. Tracked in ADFA-7250.

Troubleshooting

When Connect fails, tap Show details under the message to see every request it sent and everything the server answered: status line, headers and body. The token, extra header values, cookies and the Mcp-Session-Id are hidden — only their scheme (such as Bearer) and length remain — and so are the URL's user:password@ part and its query values. A key the server puts in the URL path cannot be told apart from the path, so check the first line before you Copy the transcript into a bug report. A WWW-Authenticate header on a 401 usually says what the server expected instead.

  • "has no MCP endpoint at that URL" — the path is wrong; try adding /mcp.
  • "does not accept this request" — the server is probably not a Streamable HTTP MCP server.
  • "refused the access token" — re-enter it; the field shows Stored rather than the value, so typing replaces it. If the server needs no token at all, use Clear stored credential.
  • "refused the Authorization extra header" — an extra header named Authorization is sent instead of the access token. Its value needs the scheme in front: Bearer <token>, or for an Atlassian API token Basic followed by the base64 of email:token. In Show details, a hidden value with no scheme in front of it means the scheme is missing.
  • Tools do not appear in the Agent — check the server is enabled, at least one tool is switched on, and AI Core is installed and active.
  • Everything times out on mobile data — some servers are slow to handshake; try again on Wi-Fi before assuming the URL is wrong.
  • "The app … did not answer" — the SQLite debugger entry's app gave no answer. Android may pause an app in the background: bring the app to the front and try again.
  • "The app … is not running with the SQLite debugger" — nothing answers on the app's SQLite debugger port: the app has stopped, or it was rebuilt without the SQLite debugger. Open the app again from Code on the Go.
