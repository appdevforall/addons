Vector Search Plugin

Executive overview

Vector Search adds semantic, meaning-based results to Code on the Go's project search. Instead of matching only exact text, it ranks code by similarity of meaning, so a search for "read a file into a string" can surface the relevant method even when those exact words don't appear.

It is a headless plugin — it has no screens of its own. It contributes an extra "Semantic Results" section to the existing project search.

Core functionality

  • Semantic project search — contributes ranked results via the IDE's project-search extension point.
  • Indexing — walks the project (capped, skipping build/.git and similar), chunks files by language-aware boundaries, embeds those chunks in batches, and stores the vectors in a local SQLite database.
  • Routed through your own AI selection — it embeds with the backend you chose in AI settings and that backend's embedding model. It names no provider of its own.
  • Versioned vectors — every row records the backend, model and width that produced it; a search only ranks vectors of the same origin, and changing either builds the index again.
  • Cosine-similarity ranking with a relevance cutoff so only strong matches are returned.

Technical architecture

ComponentRole
VectorSearchPluginEntry point. Implements ProjectSearchExtension; runs indexing on a background scope and answers search requests.
EmbedderResolverResolves the selected backend to an EmbeddingBackend, or says which of the reasons it could not.
CodeChunkerSplits files into small, language-aware chunks with overlap for context.
EmbeddingBatchesGroups chunks into batched calls so a large project is never held in memory whole.
EmbeddingIndexingServiceCollects files and stores chunk vectors, with their provenance, in a local SQLite database (embeddings.db).
ReindexDecisionDecides whether the existing index can answer the query, or has to be built again.
VectorMath / VectorSearchServiceCosine similarity and top-K ranking of stored embeddings against the query.

Embeddings are requested through AI Core's inference service over the shared service registry; the plugin contains no model, no HTTP client and no native code of its own.

Usage

  1. Install AI Core and an agent plugin whose backend embeds (OpenAI or Gemini), then select it in AI settings and give it a key.
  2. Install Vector Search via the Plugin Manager and restart the IDE.
  3. Use the IDE's project search. Semantic matches appear under a "Semantic Results" section. The first search on a project triggers a background index build.
Privacy: the index is a local SQLite database, but the chunk text is sent to the backend you selected in order to be embedded — indexing a project sends its source to that provider. Vector Search never picks a backend for you: with none selected, nothing is sent and nothing is indexed.

Key benefits

  • Find code by meaning — surfaces relevant code even without an exact keyword match.
  • Honest about what it is — with no embedder available it contributes nothing, rather than presenting word matches as semantic ones.
  • Provider-neutral — it follows your AI selection and gains any new backend that embeds, with no change here.
  • Lightweight — no bundled model or native libraries; a compact SQLite index.
