Vector Search — Semantic Code Search

Vector Search adds meaning-based search to the project. Instead of matching exact text, it ranks code by semantic similarity to your query and contributes a "Semantic Results" section to the project search screen.

How it works

  • Project files are split into chunks and turned into embedding vectors.
  • Your query is embedded the same way and compared by cosine similarity; the closest chunks are returned.
  • Embeddings come from the AI backend you selected in AI settings, using the embedding model chosen on the Semantic Search screen. The backend must be one that produces embeddings, which today means a cloud one.

What you need

  • The AI Core plugin, which publishes the inference service.
  • An agent plugin whose backend can embed — OpenAI or Gemini — selected in AI settings and configured with a key.

With none selected, Vector Search contributes no results at all. It does not fall back to matching on words: word matches presented as semantic ones look like the feature working badly rather than not running.

Using it

Open the project search screen and run a query as usual. When Vector Search is active, results include a Semantic Results section alongside the normal text matches. Indexing happens on demand for the searched roots.

The Semantic Search screen

Open Preferences → Configuration → Semantic Search. The screen updates on its own when you switch backend or model in AI settings.

  • AI backend — the backend selected in AI settings, its chat model, and whether it works with Vector Search. Supported means it can embed your code and offer its embedding models here. Not supported means it cannot, or its plugin is too old to: update its plugin (newer Gemini and OpenAI plugins support Vector Search), or select one that does in AI settings. The on-device Local backend never does. If no backend is selected, or AI Core is not installed, the screen says so instead.
  • Embedding model — the models the backend can embed with right now, for example the Gemini models that support embedContent. Picking one stores it in the backend plugin's own settings, and the next search rebuilds the index with it. If the list cannot load (no API key, no network), the field still shows the model in use and the reason appears beneath it. This setting used to live in the Gemini and OpenAI settings panes; a model chosen there before is the one selected here.
  • Privacy line — names the backend your source code is sent to when the project is indexed.
  • Index — leads with the state of the open project's index: Up to date (built with the selected backend and model), Out of date (built with another model; the next search rebuilds it), Indexing (a build is running, with a progress bar), Last build failed (nothing was stored; fix the backend's key or quota, then clear the index to try again), Not indexed yet (no search has run since the index was built or cleared) or No project open. Below it: the number of chunks and files indexed, the model and vector size, and when the index was last built.
  • Clear index — asks for confirmation, then deletes the index of every project, not only the open one. The next search rebuilds it, which sends the project's source to the selected backend again. Clearing while an index is being built waits for that build to stop first, so no partial index is left behind.

Long-press any control on the screen for a short explanation.

Changing provider or model

Every stored vector records which backend, model and vector width produced it, and a search only ever ranks vectors from the embedder it is querying with. Switching provider, or changing the embedding model on the one you have, therefore builds the index again from scratch — vectors from two different models cannot be compared, and comparing them anyway returns plausible-looking nonsense rather than an error.

Privacy

Indexing reads files in the current project only, and the vectors are stored in a local database on the device. The chunk text itself is sent to the backend you selected in order to be embedded, so indexing a project sends its source to that provider. That is why Vector Search never picks a backend for you: with nothing selected, nothing is sent and nothing is indexed.

Troubleshooting

  • No semantic results at all — open the Semantic Search screen: it says whether AI Core is installed, which backend is selected, and whether that backend supports Vector Search, with what to do if it does not.
  • No results on the first search — the roots may still be indexing; run the search again once it completes.
  • Results stopped appearing after a settings change — changing the embedding model empties the index and builds it again; the first search afterwards pays for that, and its results title says the index was rebuilt.
  • Results look stale or wrong — use Clear index on the Semantic Search screen; the next search builds a fresh one.
