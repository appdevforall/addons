Vector Search — Semantic Code Search

Vector Search adds meaning-based search to the project. Instead of matching exact text, it ranks code by semantic similarity to your query and contributes a "Semantic Results" section to the project search screen.

How it works

  • Project files are split into chunks and turned into embedding vectors.
  • Your query is embedded the same way and compared by cosine similarity; the closest chunks are returned.
  • Embeddings come from the AI backend you selected in AI settings, using that backend's own embedding-model setting. The backend must be one that produces embeddings, which today means a cloud one.

What you need

  • The AI Core plugin, which publishes the inference service.
  • An agent plugin whose backend can embed — OpenAI or Gemini — selected in AI settings and configured with a key.

With none selected, Vector Search contributes no results at all. It does not fall back to matching on words: word matches presented as semantic ones look like the feature working badly rather than not running.

Using it

Open the project search screen and run a query as usual. When Vector Search is active, results include a Semantic Results section alongside the normal text matches. Indexing happens on demand for the searched roots.

Changing provider or model

Every stored vector records which backend, model and vector width produced it, and a search only ever ranks vectors from the embedder it is querying with. Switching provider, or changing the embedding model on the one you have, therefore builds the index again from scratch — vectors from two different models cannot be compared, and comparing them anyway returns plausible-looking nonsense rather than an error.

Privacy

Indexing reads files in the current project only, and the vectors are stored in a local database on the device. The chunk text itself is sent to the backend you selected in order to be embedded, so indexing a project sends its source to that provider. That is why Vector Search never picks a backend for you: with nothing selected, nothing is sent and nothing is indexed.

Troubleshooting

  • No semantic results at all — check AI settings: AI Core must be installed, a backend selected, and that backend must be one that embeds. The on-device backend does not.
  • No results on the first search — the roots may still be indexing; run the search again once it completes.
  • Results stopped appearing after a settings change — changing the embedding model empties the index and builds it again; the first search afterwards pays for that.
