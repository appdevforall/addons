Rust Tools

Build, run, test, and format Rust programs on the device, straight from the editor toolbar.

Rust Tools adds two project templates and four toolbar commands. The commands appear only while a Rust project is open; in a Java, Kotlin, or Android project the toolbar is left alone. Because Gradle plays no part in a Rust project, the Gradle actions (Quick Run, Sync, Debug, Run Tasks, Launch App) are hidden while you work in one.

A project counts as Rust when its root holds a Cargo.toml or any .rs file, and no Gradle build script.

Getting the Rust toolchain

The Rust toolchain ships inside the plugin: rustc, cargo, rustfmt, rust-analyzer, the standard library and its source, and the clang and lld linker. The first time the plugin activates it unpacks them into its own private directory - no download and no network. It takes about 600 MB on the device and happens once.

The toolchain is built for 64-bit ARM (arm64-v8a) only, so Rust Tools needs the 64-bit build of Code on the Go. On the 32-bit build the plugin tells you so and adds no commands.

Every command streams its output into the Build Output panel at the bottom of the editor, and the panel opens itself when a command starts. While a command is running its toolbar button turns into a Cancel button: tap it to stop the process.

Run app

Runs cargo run in the project root. Cargo compiles the crate and then replaces itself with your program, so the process the IDE tracks is your program and Cancel really stops it - which matters most for a server.

Build output goes to the plugin's private directory, not to a target folder in your project. Android does not let programs start from the device's shared storage, where your projects live, and builds there are also slower.

Run current file

Compiles exactly the .rs file open in the editor with rustc and runs it - useful for a scratch program that is not part of the crate. Open a .rs file before tapping it.

A single-file build sees only the file you point it at, so it needs a main function and cannot use other modules or crates. For anything larger, use Run app.

Format code

Runs cargo fmt, which rewrites every .rs file in the crate to the standard Rust style. It works on the files on disk, so save your changes first. A rustfmt.toml in the project root adjusts the style.

Run tests

Runs cargo test: unit tests, integration tests in tests/, and the examples in documentation comments. The test runner is part of the toolchain, so tests work offline.

Editing

  • Syntax highlighting for .rs files, from a tree-sitter grammar.
  • Completion, diagnostics, go to definition, references, and formatting from rust-analyzer, which starts the first time you open a .rs file.

Crates and the network

Both templates use only the standard library, so they build, run, and test with no connection. Adding a crate under [dependencies] in Cargo.toml needs a connection once, while cargo downloads it from crates.io; after that it builds offline.

The templates

Rust Starter is a minimal crate: a greet function, a main that calls it, and a unit test so Run tests has something to run on the first tap.

Rust HTTP Server is a std::net server with an HTML landing page and a JSON /api/status route, one thread per connection, and read and write timeouts. Run it and open http://localhost:8080 in a browser on the same device.

Both ask for a crate name when you create them - what goes on the name line of Cargo.toml. Use lowercase letters, digits, and underscores.
