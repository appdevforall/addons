PHP Tools

Write, run, and test PHP on the device, websites included, with no network connection.

PHP Tools adds two project templates, editing support for PHP files, and up to five toolbar commands. The commands appear only while a PHP project is open; in a Java, Kotlin, or Android project the toolbar is left alone. Because Gradle plays no part in these projects, the Gradle actions (Quick Run, Sync, Debug, Run Tasks, Launch App) are hidden while you work in one.

A project counts as PHP when its root holds a composer.json, or a .php file sits in the root, src/, or public/, and there is no Gradle build script.

Getting PHP

PHP 8.5, Composer, and the phpactor language server ship inside the plugin, with a PHP build for both 64-bit and 32-bit ARM devices. The first time the plugin activates it unpacks the build for this device into its own private directory - no download, no network, and nothing is installed into the shared terminal environment. It happens once; a message tells you when PHP is ready.

PHP comes with its common extensions built in: mbstring, intl, json, pdo_sqlite and sqlite3, pdo_mysql, curl, openssl, dom, xml, zip, gmp, bcmath, and more.

PHP is not installed with pkg. The plugin carries Termux's build of PHP together with the libraries it loads, and its own php.ini, which points PHP's temporary files, its cache lock, and its certificate bundle at directories an app can use.

Editing

.php and .phtml files get syntax highlighting from a tree-sitter grammar, and completion, hover, signature help, go to definition, find references, and code actions from the phpactor language server. The server starts when you open the first PHP file and stays running while the project is open. If you open a file before the first install has finished, close and reopen it once PHP is ready.

Every command streams its output into the Build Output panel at the bottom of the editor, and the panel opens itself when a command starts. While a command is running its toolbar button turns into a Cancel button: tap it to stop the process.

Run app

Runs, in order of preference:

  • the start script from composer.json. A script of the form php ..., such as php -S localhost:8080 -t public, runs PHP directly, so the process the IDE tracks is your program and Cancel really stops it. Any other script runs through composer run-script start;
  • PHP's built-in web server on localhost:8080 with public/ as the document root, when there is a public/index.php;
  • the first of index.php, main.php, app.php, src/main.php, and src/index.php, as a command-line program.

Open a website in a browser on the same device while it runs. Requests for files that exist under public/ are served as they are; every other request goes to public/index.php.

Run current file

Appears while a .php file is open, and runs exactly that file with PHP - useful for a scratch script that is not the project's entry point.

Run tests

Runs PHPUnit when Composer has installed it in vendor/bin, or the test script from composer.json. Otherwise it runs every tests/*Test.php file with assertions turned on (zend.assertions=1, assert.exception=1): a failed assert() throws, the file exits with an error, and the run fails. That needs no packages, so tests work offline.

Check syntax

Runs php -l on every .php file outside vendor/ and lists each file with its result. The command fails if any file has a syntax error.

Install dependencies

Appears when the project has a composer.json, and runs composer install in the project root.

This is the one command that needs a network connection for any package from Packagist. A project that uses only PHP's built-in functions never needs it - which is why the bundled templates have no dependencies, and run fine with no connection at all.

The templates

PHP Script is a command-line program: a Greeter class, a main.php that uses it, and tests for the built-in test runner.

PHP Web App is a website on PHP's built-in web server: an HTML page, a JSON /api/hello route, a 404 for anything else, a stylesheet served as a static file, and tests that call the request handler directly. It asks for the port to listen on.

Both ask for a Composer package name when you create them.

Build environment

  • php, composer, and phpactor are on the PATH. php is a small launcher that points LD_LIBRARY_PATH at the libraries bundled with it and PHPRC at the plugin's php.ini.
  • php.ini sets the temporary directories and OPcache's lock file to the IDE's temporary directory, points openssl.cafile and curl.cainfo at the terminal's certificate bundle, and raises memory_limit to 512 MB.
  • Composer keeps its home and cache in the plugin's private directory, and its scripts are never stopped by Composer's own timeout.

Limits

  • Programs cannot read keyboard input: nothing typed reaches STDIN of a command. Pass values as arguments instead, or run the program from the terminal.
  • The built-in web server runs one request at a time. It is for development, not for serving other devices.
