1. Executive Overview

Fun and Games LibGDX is a template bundle for Code on the Go. It adds three small Android games built with libGDX to the New Project screen. Instead of starting from an empty activity, a developer picks a game, enters an app name and package name, and gets a complete project that builds and plays on the device straight away. They are libGDX ports of the games in Fun and Games JME.

It runs no code. A .cgt bundle is a zip archive of project skeletons and their metadata, which the IDE reads directly. There is nothing to enable, no permissions to grant, and no process to load.

2. Core Functionality

The three templates

TemplateLanguageGame
Demo (libGDX)JavaA 3D Earth you drag to spin, an orbiting rocket with an exhaust trail and bloom glow, and a starfield. Tap for points.
Tetris (libGDX)KotlinThe falling-block puzzle.
Bubble Wand (libGDX)KotlinA first-person shooter: catch floating balloon animals in bubbles.

Controls

GameControls
DemoDrag to rotate the Earth, flick to spin it with inertia, tap for +10 points.
TetrisDrag left or right to move, drag down to soft-drop, tap to rotate, long-press to hard-drop.
Bubble WandLeft half: drag to walk. Right half: drag to look, tap to shoot. Or use the on-screen D-pad and FIRE. HIDE UI toggles the buttons.

A hardware keyboard also works: arrow keys, space and WASD.

What each template generates

  • A Gradle project with an app module, a version catalog (gradle/libs.versions.toml) and the Gradle wrapper.
  • The game source under app/src/main/java/, in the package you entered.
  • libGDX 1.13.1 in app/libs/, which the build uses directly.
  • Launcher icons, and for Demo the Earth and particle textures it draws.

Parameter substitution

The app name and package name entered in the New Project dialog are substituted into the generated files. The Android Gradle Plugin, Kotlin, Gradle, SDK and Java versions are taken from the IDE, so a generated project follows whatever toolchain the installed Code on the Go ships.

3. Technical Architecture

What is in the archive

A .cgt is a zip archive. Its root holds templates.json, which lists the templates, and one directory per template. Each of those carries template/template.json for its name, description and parameters, and template/thumb.png for the picture on the New Project screen.

fun-and-games-libgdx.cgt | +-- templates.json lists the three templates +-- cgt-build.properties the commit this bundle was built from | +-- demo/ | +-- template/template.json | +-- template/thumb.png | +-- settings.gradle.peb | +-- gradle/libs.versions.toml.peb | +-- app/build.gradle.peb | +-- app/src/main/java/PACKAGE_NAME/CubeGame.java.peb | +-- app/libs/gdx-1.13.1.jar and the other libGDX files | +-- tetris/ ... and bubblewand/

Authoring with Pebble

Files ending in .peb are processed by the Pebble template engine at project-creation time (${{APP_NAME}}, ${{PACKAGE_NAME}} and friends are substituted) and the suffix is dropped; other files are copied verbatim. This is the same authoring format the core Android templates use.

How the IDE finds it

Code on the Go lists the .cgt archives it finds in the Downloads folder in the Extensions Manager, marked Not installed. Installing one with the + button, as described under Usage, is what adds its templates to New Project.

Provenance

Every published bundle carries cgt-build.properties at its archive root, recording the commit it was built from and the date of that commit. Read it with unzip -p fun-and-games-libgdx.cgt cgt-build.properties.

Permissions

None. A template bundle declares no permissions, because it runs no code. The IDE writes the generated project, exactly as it does for a built-in template. The games themselves request no Android permissions either.

4. Usage

Install

  1. Download fun-and-games-libgdx.cgt from the add-on gallery.
  2. In Code on the Go, open Preferences → Extensions Manager and switch to the Templates tab.
  3. Tap +, browse to the downloaded .cgt and select it.
  4. A dialog lists the three templates. Tap Install.

Create and run a game

  1. Open New Project.
  2. Pick Demo (libGDX), Tetris (libGDX) or Bubble Wand (libGDX).
  3. Enter an app name and a package name, then tap Create.
  4. Wait for Project initialized, then tap Run.
libGDX comes with the bundle. Each generated project already holds libGDX in app/libs/, so the first build does not download it. AndroidX comes from Code on the Go's own offline repository.

5. Key Benefits

  • Playable from the first build. Each template is a finished game, not a skeleton, so there is something to run and change straight away.
  • A widely used game framework. libGDX brings 2D and 3D rendering, input and audio to a project made on the device.
  • Java and Kotlin. Demo is written in Java, Tetris and Bubble Wand in Kotlin.
  • Follows the IDE's toolchain. Plugin, language and SDK versions come from Code on the Go, so the projects keep building as the IDE updates.
  • No code, no permissions. A data bundle the IDE reads. Nothing loads into the editor's process.

6. Limitations & Scope

  • Generated projects build for armeabi-v7a and arm64-v8a only. That covers every phone and tablet that runs Code on the Go, but not x86 emulators.
  • The bundle is about 8 MB, because it carries the libGDX files for each game.
  • All three games use libGDX 1.13.1. Do not drop to 1.12.x: its native library is not 16 KB-page aligned, and Google Play Protect blocks the builds.
