Native Logging Demos

Two projects that show how to write to Code on the Go's App Logs window from C and from C++

Version 1.0.0 · Author: James Turner · Template bundle: org.appdevforall.nativeloggingdemos

Overview

When you run a debug build, Code on the Go's App Logs window shows what your app writes to the Android log. This bundle adds two templates to the New Project screen that write to it from native code. Each project has one button. Tap it, and the native code writes a short series of log lines, all with one tag so they are easy to find.

TemplateTagWhat it shows
Native Log Demo (C)NativeDemoCC11. LOGD-style macros over __android_log_print, __android_log_write, your own wrapper with __android_log_vprint, a compiler-checked helper that adds the function and line, reporting errno, and logging from a second thread.
Native Log Demo (C++)NativeDemoCppC++17. A type-safe logx::info() << ... stream logger, an RAII timer that logs how long a scope took, containers and your own types, an exception message, and a std::thread.

Both let you choose Kotlin or Java for the activity that calls the native code.

Requirements

  • The NDK-Installer plugin. It installs the NDK and CMake the projects build with. Install it from the add-on gallery first.
  • A debug build. App Logs receives lines only from debug builds.
  • The project open in the editor while the app runs.
  • A 64-bit ARM device. The projects build for arm64-v8a only.

Usage

Install

  1. Download native-logging-demos.cgt from the add-on gallery.
  2. In Code on the Go, open Preferences → Add-ons Manager and switch to the Templates tab.
  3. Tap +, browse to the downloaded .cgt and select it.
  4. A dialog lists the two templates. Tap Install.

Create and run a demo

  1. Open New Project and pick Native Log Demo (C) or Native Log Demo (C++).
  2. Enter an app name and package name, choose Kotlin or Java, and tap Create.
  3. Run the debug build.
  4. In the app, tap Write to App Logs.
  5. Open App Logs in Code on the Go and type the tag in its filter box.
Why not printf? Android throws away an app's standard output, so printf and std::cout never reach App Logs. Write through <android/log.h> instead, as these demos do.

Limitations

  • The demos do not log at the fatal level. App Logs does not recognise it and shows such a line as raw text.
  • A release build writes the same lines to the Android log, but App Logs does not receive them.
